## 2026-09-03 (4) — YCB 상품 에셋 + 상품 배치

**한 일**
- `tools/ycb_catalog.py` — YCB 구글 스캔(16k 면) 85개를 S3 에서 받아 USD 크레이트로 변환. 원점을 밑면 중심으로 맞추고 텍스처·강체·convexHull 콜라이더·질량을 붙였다. 치수는 메시 AABB 에서, 질량은 YCB 논문 Table I 에서. 84종 카탈로그(`assets/ycb/catalog.json`) 커밋
- `scene/stock.py` — 진열대 슬롯에 상품을 채운다. 통로별 품목군(플래노그램), 같은 상품 2슬롯 페이싱, 앞뒤로 최대 3개, seed 모드에서 빈 자리·순서 랜덤. store.usda 를 서브레이어로 깔고 진열대 프림 아래 `Stock/Item_NN` 으로 얹는다 (진열대 로컬 좌표, 인스턴싱)
- `tools/verify_stock.py` — 9,864개 전부 슬롯 안·선반 접촉·비겹침·물리 API 확인. 7항목 통과
- 트윈 모드 결과: 상품 9,864개, 137대, 32종

**결정과 이유**
- 에셋을 `.usda` 가 아니라 `.usd`(크레이트) 로. 16k 면 메시가 텍스트면 6 MB, 바이너리면 0.3 MB
- 상품을 진열대 프림의 **자식**으로 두어 로컬 좌표로 놓는다. 진열대 회전·위치를 다시 계산할 필요가 없고, 검증도 `ComputeRelativeBound` 로 진열대 프레임에서 바로 한다
- 프림 이름 `ycb_<id>` — USD 프림 이름은 숫자로 시작하거나 하이픈을 가질 수 없다 (`027-skillet`)
- 질량은 논문 표를 pdftotext 로 뽑아 대조했다. 처음 기억으로 적은 값 중 cracker box(411→453), mustard(603→431), spatula(51.5→105) 가 틀렸다. 표에 없는 4개(bleach, mini soccer, baseball, rubik) 는 웹 목록 값이라 주석으로 표시
- 한계: YCB 에서 마트 상품으로 쓸 만한 것은 32종. 생활용품은 3종뿐이라 그 통로는 단조롭다. GSO 확장이 다음 순서

**렌더에서 배운 것**
- instanceable 프림 안은 `Usd.PrimRange(prim, Usd.TraverseInstanceProxies())` 로 순회해야 메시가 보인다. 검증기가 처음엔 이걸 몰라 참조 실패로 잘못 판정했다
- YCB 텍스처 PNG 가 한 장에 최대 11 MB (85장 430 MB). 렌더가 느리면 다운스케일한다

**Isaac GUI 스트리밍**
- EC2 에는 디스플레이도 DCV 도 없다. Isaac Sim 6 에 들어 있는 `isaacsim.exp.full.streaming` 앱을 `--no-window` 로 띄우면 WebRTC 로 GUI 가 나간다 (`tools/view_isaac.sh`). 공인 IP 를 `primaryStream.publicIp` 로 넘겨야 NAT 뒤에서 ICE 가 붙고, `quitOnSessionEnded=false` 로 둬야 클라이언트가 끊겨도 앱이 안 죽는다
- 포트: TCP 49100 시그널링, UDP 47998 미디어. 보안그룹은 인스턴스에 AWS 자격증명이 없어 여기서 못 연다 — 콘솔에서

**남은 것**
- 상품 채운 매장 Isaac 렌더 확인 → README 그림 (완료)
- GSO 로 상품 확장, `scenario.py`

## 2026-09-03 (3) — 대형마트 규모로 확장, Isaac 렌더

**한 일**
- 매장 규모를 동네 마트(부통로 2개, 5.6 × 11.2 m)에서 **대형마트 식품 매장 일부**(부통로 8개, 25.6 × 17.6 m, 진열대 137대)로 확장
- 기둥을 수동 좌표 1개 → **그리드**(9.6 × 8.4 m)로. x 는 곤돌라 열 간격의 배수라 기둥이 열 위에 온다. 기둥이 떨어진 자리의 진열대는 `placements()` 가 비운다
- `tools/render_isaac.py` — Isaac Sim 6 헤드리스 RTX 렌더 (overview / aisle / shelf_face / main_aisle 네 시점). README 그림을 실제 렌더로 교체
- 재질 추가: 진열대 흰색 분체도장 강판·회색 지주·검은 걸레받이, 벽·천장·기둥 백색. 조명 3000 → 12000, 4000K → 5000K
- 검증 82항목 전부 통과 (통로 10개, 입구 16곳)

**결정과 이유**
- 사용자 요구: "이마트·홈플러스 같은 대형마트". 규모는 통로 수·길이·폭·천장·기둥 그리드로 결정되고 생성기라 상수만 바꾸면 되지만, 기둥이 진열대 열 안에 떨어지는 문제는 **배치 규칙**(그 자리 비우기)이 필요했다. 실제 매장이 그렇게 한다
- 부통로 2.2 m, 주통로 3.5 m, 천장 5.0 m, 벽면 진열대 2.4 m — 전부 [잠정]. 대형마트 설계 관행의 대표값
- 매장 전체를 재현하되 실측은 부통로 1~2개만 한다는 원칙은 유지. 곤돌라 규격·통로 폭이 매장 안에서 반복되기 때문
- matplotlib 3D 는 137대 규모에서 앞뒤 정렬이 깨져 포트폴리오 그림으로 못 쓴다. EC2 에 Isaac Sim 6 + A10G 가 있으니 실제 렌더로 간다

**렌더에서 배운 것**
- BasicWriter 는 상대경로를 `~/omni.replicator_out` 아래로 푼다 → 절대경로로
- RayTracedLighting 모드는 간접광이 약해 렌더용 돔 라이트(1000)를 얹어야 그림자가 검게 안 나온다. 장면 USD 에는 넣지 않는다
- 첫 렌더는 카메라가 벽 밖에 있어 회색 상자만 찍혔다. 매장은 닫힌 상자라 전체 뷰도 천장 모서리 안쪽에서 찍어야 한다
- 결과가 전체적으로 세피아 톤이다. 색온도·돔 라이트 색을 손볼 여지가 있다

**남은 것**
- YCB 상품 선별 → `stock.py` (중단된 상태에서 재개)
- 렌더 색감 조정, 부통로 안 카메라를 AMR 카메라 높이로

## 2026-09-03 (2) — 매장 생성기, 실제 곤돌라 구조 반영

**한 일**
- `scene/store.py` — 매장 한 구역 생성기. 주통로·부통로, 벽면 진열대, 양면 곤돌라 + 엔드캡, 기둥, 천장, 통로별 라인 조명, 60 cm 타일 바닥(텍스처)
- `scene/shelf.py` 를 상자 3장 모델에서 **실제 곤돌라 구조**로 교체 — 뒤쪽 지주 2개 + 백판, 깊은 바닥 데크 + 걸레받이, 얕은 상단 선반, 가격표 레일, 홀 피치 스냅
- `tools/verify_store.py` — 매장 구조 대조 + AMR 통행(직진·회전·통로 입구) 42항목
- `tools/verify_shelf.py` 를 새 구조에 맞게 갱신 — 58항목
- `tools/plan_store.py` (평면도), `tools/render_3d.py` (3D PNG/GIF) — README 그림은 전부 USD 에서 자동 생성
- 실측 안내(`docs/SURVEY.md`)에 주통로·타일·상단 선반 깊이·엔드캡 항목 추가

**결정과 이유**
- "최대한 실제 마트와 같게"를 **구조 우선**으로 해석했다. 치수는 실측 전이라 어차피 잠정값이지만, 구조(측면 개방, 데크/상단 깊이 차, 레일 턱, 주·부통로, 엔드캡)는 실측 후에도 바뀌지 않고 로봇 동작에 직접 영향을 준다
- 부통로 기본값을 1 → **2** 로. 1 이면 양면 곤돌라와 엔드캡이 생기지 않아 실제 마트 구조를 시험할 수 없다
- 최상단 선반을 1.60 → **1.50** 으로. 손이 닿는 진열 관행에 맞추면서 최상단 여유가 30 cm 가 되어 이전의 "크래커·병 안 들어감" FAIL 이 사라졌다. 실측 전 잠정값이라는 사실은 그대로다
- 통행 검사는 constants 가 아니라 **USD 안의 AABB** 로 한다. 배치 코드의 회전·오프셋 실수는 constants 만 보면 못 잡는다
- 주통로 전체에 "제자리 회전" 조건을 걸었더니 벽에 붙은 기둥 하나로 FAIL 이 났다. 회전은 **부통로 입구에서만** 필요하고, 장애물은 x 든 y 든 한 축으로 비키면 되므로 그렇게 바꿨다
- 잠정 기둥은 벽선에 묻혀 주통로로 10 cm 튀어나오는 위치에 뒀다. 검증 경로가 실제로 동작하는지 보기 위한 것이고, 실측하면 튜플을 통째로 교체한다

**남은 것**
- 실측 (`docs/SURVEY.md`)
- YCB / GSO 에서 슬롯 치수에 맞는 상품 선별 → `stock.py`
- Isaac Sim 에 `out/store.usda` 올려 렌더 확인, README 의 GIF 를 실제 렌더로 교체

## 2026-09-03 (1) — 진열대 생성기 + 대조 검증

**한 일**
- 레포 생성. `scene/constants.py` (치수 단일 진실 공급원, 출처 태그 `[실측][잠정][표준][설계]`), `scene/shelf.py`, `tools/verify_shelf.py`, `docs/SURVEY.md`
- macOS 노트북에서 `usd-core` 만으로 생성 → EC2 로 옮겨 같은 결과 재현 확인

**결정과 이유**
- **CAD·Blender 를 쓰지 않는다.** 마트 구조물은 직육면체라 파이썬 상수가 더 정확하고, 변환 사슬에서 UV·머티리얼이 깨진다
- **상품은 스캔 데이터셋(YCB / GSO)** 을 쓴다. SKU 모델링은 끝이 없다
- **생성기는 Isaac 없이 돈다.** 무거운 시뮬레이터 없이 형상을 반복한다
- 생성 결과는 **되읽어 숫자로 대조**한다. 눈으로 보는 검증은 회전·오프셋 실수를 놓친다
- 단별 여유 높이를 하나의 값으로 두지 않는다. 최상단은 위에 판이 없어 다르다

**남은 것**
